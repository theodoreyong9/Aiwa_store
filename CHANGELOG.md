# Changelog

## Unreleased

- Initial import of the protocol (`packages/core`), the distribution layer (`packages/platform`) and the wallet API (`packages/lib`) into one workspace, with their tests (core 410, platform 85, lib 95). One lock file; the packages depend on each other through the workspace, not through pinned commits.
- Plain-words explanation in English and French.
- The creator fee: a deployment may set `rewardParams.creatorFee = { address, rateOfT }`. A fixed part of the T share of every burn then goes to that address in the same transaction; readers count it and refuse a commitment at T > 0 whose burn did not pay it. Core 418 tests, lib 100.
- Yellow paper rewritten as a standalone specification (version 1.0), with the creator fee (§11).
- `registry`: app packages signed by their author (`aiwa-app/1`), validation of submissions by pull request with `assessSubmission` (the burns confirmed by the registry itself, the creator fee included), the existing `score / laps` ranking, the permission ratio, refresh; a workflow that reads the submission as data and writes `store/`. 13 tests.
- `apps/web`: the store (ranked list, search, apps in `<iframe sandbox="allow-scripts">`, offline), the wallet (the burn shows the creator fee before signing, send/receive, recovery), publishing (a signed package with the mining evidence, as a pull request). Tested in Chromium.
- `android`: the dictation widget and its Termux backend, now an optional module; one mode, `store` (Claude writes one self-contained HTML app, which opens in the Store's publish sheet), replaces the two modes tied to other projects; the Store runs in a WebView served from the APK's assets; the module starts only once the widget is added or its screen opened. CI builds the APK. Backend 68 tests.
- `docs/BUSINESS.md`.
- Protocol cleanup, no change to what is signed: one signing module for every signed action (`aiwa-core/src/signing.js`; the messages' bytes are pinned by a test), shared hex/hash/base58 helpers, history-style comments removed; `aiwa-lib`'s 1,581-line wallet split into a thin `AIWA` facade over `ledger`, `mining`, `burns`, `payments`, `channel`, `observer`, `backup` and `evidence`. A test that failed one run in six (a hand-rolled base58 that dropped a leading zero byte) is fixed.
- The wallet starts by itself and the Recovery panel is gone: the first tap creates it, the 12 words are kept in the phone's keystore, its history comes back by itself (Android's backup, archive nodes if the deployment lists any, the registry's public baseline of the author). The registry now publishes `store/baselines/<author>.json`.
- Two kinds of app in the store, both submitted on GitHub: `code` (the package carries the HTML) and `aiwa` (the package carries a pointer to a signed bundle published through Aiwa; the registry and the Store both verify it against the pinned manifest id). The Aiwa SDK is built as one module (`lib/aiwa.js`) for such apps, with an example.
- Publishing from the widget: the Publish tab is replaced by one sheet, opened by the ▦ button, that signs with the wallet and opens the pull request on the author's GitHub account (GitHub's device flow, run by the Android app; the token and the 12 words in the Keystore). A browser hands the signed file over instead.
- `android`: the `aiwa` deploy mode next to `store` (backend 73 tests), the `github-login` and secret commands of the host channel, automatic backup (secrets excluded).
