# Changelog

## Unreleased

- **design-research: a script that studies reference interfaces and hands Claude Code measurements.** `design-research/` visits sites of Awwwards and CSS Winner (Site of the Day) in Chromium with Playwright and the Chrome DevTools Protocol (network, animations, performance, console, canvas contexts), measures type, composition, motion, interaction, rendering and palette by written rules, detects technologies with status, confidence and evidence (a library is OBSERVED only when the page shows it), says for each of site / pwa / apk / contract UI what of the reference can be used, keeps one canonical entry per site in `catalog/sites.jsonl` with pictures and stored observations, and turns a brief into a research pack (`.research/latest/`: references, shared patterns, measured ranges, pictures). A weekly workflow updates the catalogue. Tested against local pages; the two registry parsers were not run against the live sites (no network where they were written), and the registries' terms on automated reading are not checked. `design-research/README.md` lists the limits. The widget's instructions now tell Claude Code, whenever there is an interface to make, to clone the Store read-only and run `design-research research` against the published catalogue before designing, then to use the pack (patterns several references share, never a copy); if the catalogue is empty or unreachable it says so and goes on. The catalogue is empty until the first run of the weekly workflow.
- **The ceiling of the reward formula is gone.** `rewardFixed` returned nothing, so a gain of 0, for any single result above 10^12, instead of limiting it: it did not bound AIWA's production (that is not defined: each reader counts what it accepts), and it would have paid the biggest producer nothing. It was never reachable with the reference parameters (billions of years for 1 SOL, thousands of years for a million). Nothing else changes: there is still no maximum supply.
- **The wallet no longer waits between epochs.** It used to work one epoch every 30 s, a timer of the reference wallet that nothing in the protocol asks for: a client without the wait earned more with the same capital, and nobody had a reason to keep it. The wallet now works back to back, as fast as the device can, and signs one event for what it worked in about 30 s (`progress.eventMs` in `deployment.json`; the number of epochs per event adapts to the device, so the log grows as slowly as before). It does not work before its first commitment: those epochs earned nothing and only raised the age, which slows what is accrued afterwards. Production in AIWA now depends on the speed of the device's core (measured here: 2.4 s per epoch in JavaScript, about 12 times the old pace); `progress.intervalMs` still gives one epoch per interval, for tests and demos. The figures of the yellow paper and the explainers stay counted at 120 epochs per hour and say so. The battery and the heat of a phone are not measured.
- **An app that uses the wallet can no longer pay without the player.** The door (`apps/web/src/app-door.js`) paid with no question asked, no cap and no expiry: an app that declared `<meta name="aiwa-wallet">` could empty the wallet as soon as it was open, with a banner as the only signal. That was a gap this project introduced with the door and wrote down instead of closing. Now the first `pay` of an app opens a sheet of the Store (not of the app) saying who asks, how much, to whom: the player refuses, allows that payment, or allows a **budget** until the app is closed. Inside the budget the payments go through (the click duel still plays smoothly), the first one beyond it asks again, a refusal makes the app's next requests fail for 30 s without asking, and closing the app (or Escape) answers the question with a refusal. Payments still are signed, each one, by the channel's session key; what changed is that the player's consent comes first. Two e2e tests: the door (the sheet, the budget, a budget too small for the payment, a refusal, closing while asked) and the click duel (the loser is asked, the winner is not). Yellow paper §17.2, §18.8, §20, the plain-words explanation and the plan say so. Not tried on a phone.
- **A voice button in the widget, before the mic.** It opens a sheet with the voice commands written out (dictation, the instructions after *« instruction Aiwa »*, the wake words of the always-on listening, the cancel and stop phrases) and, at the top, the switch of the always-on listening. The button is green while the listening runs. The same switch stays on the app's screen. If the switch is on but the service is not running (the phone restarted: Android does not let a microphone service start by itself), the sheet says so and a tap restarts it.
- **A flaky test of the GitHub mailbox, fixed.** A backend test of the watch put the loop's short pace back before the watch had ended: on a slow machine the thread had not yet gone to sleep, read the real 20 s and the test timed out (it failed once on `main`, passed on the branch). The short pace now stays until the watch has ended. Not a change of the backend.
- **The published code can be read afterwards, and the draft before.** The widget's `</>` button now opens the Store on the *published* code of the app Claude last sent (the version the registry lists, checked again before it is shown: the author's signature, and for a contract every file against the signed manifest), and the Store has the same `</>` on every app of its list and `#code=<id>` as an address. Before publication, the draft's code is read in the publish sheet (the ▦ button): a *Read the code before publishing* line was added there. The old `</>` (the copy received from Claude, or its GitHub file) is gone: Claude signs nothing, what counts is what the Store signs.

The sheet says *No wallet yet* (with the way out) when there is none, instead of waiting for it.

- **« Non c'est pas bon, arrête » and « stop Claude ».** Said at the end of what was heard (or « annule »), the first drops the dictation: nothing applied, nothing sent; at the read-back it is a no. « Stop », « arrête Claude », « arrête-toi » (after *instruction*, or alone as wake phrases *stop Claude* / *arrête Claude*) send Claude's session a message that asks it to stop: it reads it at its next step, it is not a hard interruption of the step in progress (the CLI has an interrupt for its own sessions; its call was not tried). A stop is done at once, never read back. Web tests 54 (30 in Chromium), bridge parser 32 tests.
- **« Mon agent, t'es sur quoi ? » (or « t'en es où ? ») wakes the listening, and what a wake-up starts is always read back.** The always-on listening now listens for two phrases, *« mon agent »* and *« instruction »* (French words that the small model knows; *Aiwa* it does not). *« Mon agent »* is also the question (*« t'es sur quoi »* and *« t'en es où »* are both understood): the phone reads the pills aloud first (*« Dépôt …, modèle …, push …, déploiement …, session … »*), then the microphone opens for instructions; *« t'en es où (là) »* said again, and the wake words said again at the start, are not taken for text for Claude. *« Instruction »* goes straight to listening. Since a wake-up has no screen to catch a mistake or a false waking, **every dictation started that way is read back before anything is applied or sent** (*« J'applique : modèle Opus 5.5, push main, dépôt Jobber. J'envoie à Claude : … Tu confirmes ? »*) and waits for *« c'est bon vas-y »*, every time; anything else, or silence, applies nothing and sends nothing (the message is copied). That one confirmation also covers the repository. Started from the widget's mic, nothing changes: only the repository asks. A false waking costs a spoken report, nothing more. 22 tests on the parser (`wakeKind`, `recapSentence`).
- **« T'es sur quoi ? »** After *« instruction Aiwa »*, *« t'es sur quoi (là) »*, *« rapport »*, *« statut »* or *« bilan »* makes the phone read the pills aloud, after what was applied in the same dictation: *« Dépôt Aiwa store. Modèle Opus 5.5. Push direct sur main. Déploiement Pages. Session … »*, with a warning when the Termux server does not answer (the values may then be old). The sentence is a plain function (`statusReport`), tested.
- **Listening all the time for « instruction » (off until turned on).** A switch on the app's screen starts a foreground service of the microphone type that listens for the word *instruction* and nothing else, and when it hears it opens a dictation exactly as if the widget's mic had been touched, with everything said after it read as instructions to Aiwa from the first word (*« instruction, modèle Opus, push main, c'est bon vas-y »*); a short beep says it is listening. The speech model is Vosk's small French one (about 41 MB, downloaded once, from the model's own site, when the switch is turned on) and runs on the phone: nothing the microphone hears is sent anywhere, which is why the phone's own recognizer, that streams the sound to its server, was not used. What it cannot do: *« Aiwa »* is not in the small model's vocabulary, so *« Hey Aiwa »* cannot be listened for (*« instruction »* is); after a restart of the phone Android refuses to start a microphone service by itself, opening the app starts it again; the phone shows its green microphone dot all along and the battery goes down faster (the CPU is held while it listens). The widget's mic window and the listening share the microphone: the listening lets go while the window is open. Not tried on a phone: the build checks that it compiles, and the SHA-256 of the model archive is not pinned (the official checksum could not be fetched where this was written; the one downloaded is kept, `VoskModelStore.lastHash`). The dictation itself (what the mic window and the listening both run) is now one class, `VoiceDictation`.
- **The widget's mic understands instructions to Aiwa itself.** What is said stays text for Claude, until *« instruction Aiwa »*: after it, the keywords of the pills are read as commands, as many as wanted and without repeating the start: *modèle* (Opus, Sonnet, Haiku, Fable, a version, *un million*, *automatique*), *push* (*main* or *branche*), *déploiement* (*Pages, Android, Store, Aiwa, aucun*), *nouvelle session* or *session* + a piece of a title, *dépôt* + its name. They are applied when *« c'est bon vas-y »* ends the dictation, then the text goes to Claude with the new settings. Words after the keyword that are not a command stay text for Claude (an *et* or *puis* between two commands is dropped). Nothing is guessed: a name that matches nothing, or several things, changes nothing and is said. A repository is never changed on a first hearing: the phone asks aloud (*« Dépôt X. Tu confirmes ? »*), then the mic opens for *« c'est bon vas-y »* once more; anything else, or silence, leaves the repository as it is and the message is not sent (it is copied). The overlay shows, while speaking, what was understood. The parser is a plain function (`VoiceCommands.kt`) with 15 tests. How a recognizer writes *Aiwa* said aloud is not known (several spellings are accepted); the voice, the questions and the mic were never tried on a phone.
